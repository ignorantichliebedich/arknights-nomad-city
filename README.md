# 游城拓荒 · 好友联机

面向 2–4 人的中文浏览器游戏，支持桌面与手机触控棋桌，使用原棋盘、原牌面和服务端规则裁定。房间支持昵称入座、准备开局、私密选牌、合法目标提示、城市设施、采集、计分及刷新恢复。

在线游玩：[游戏入口](http://106.52.74.24)。请使用创建房间时的相同协议与浏览器恢复席位。服务器已配置 IP HTTPS 证书；公网 443 放行后可使用加密入口。源码仓库：[arknights-nomad-city](https://github.com/ignorantichliebedich/arknights-nomad-city)。

首次访问提供同风格全屏提示；顶部“声音”提供唱片封面、切歌、中日角色语音、静音及音量设置。新访客默认开启背景音乐，从 Speed of Light 开始；已有明确声音偏好保留。素材接入见 [声音说明](docs/audio.md)。

手机使用独立触控布局：点击全屏后申请横屏锁定，棋盘随屏幕适配，资源留在顶部，城市和企业收进配件盘。支持触控选牌、确认盖放和双指缩放；浏览器不支持自动转向时可手动横放，席位和操作预览保留。操作与兼容性见 [手机棋桌](docs/mobile.md)。

本体与企业扩展均支持八回合完整对局。企业扩展包含罗德岛、海德兄弟、莱茵生命、富森银行、雷神工业、约翰老妈、黑钢国际和雷姆必拓；莱茵生命使用原版工程科、防卫科、结构科及全体玩家共用的激活科室。规则包为 `founders-2023.1`，逐档奖励及原牌出处见 [规则证据](docs/rules-evidence.md)。

## 更新与发布

每轮交付通过 `pnpm release:prepare --note '更新说明'` 自动递增应用版本并维护 [更新记录](CHANGELOG.md)，新增功能使用 `--type minor`。本地检查后先推送 GitHub，用户本地试玩并明确确认该版本上线后才部署云端。GitHub Actions 仅运行版本、源码、测试和构建检查。详细约定见 [开发规范](CONTRIBUTING.md) 与 [发布流程](docs/release.md)。

本轮版本供本地验收，公网维持原部署。声音设置底部和桌面顶部显示本地构建版本；用户确认对应版本上线后再更新云端。

## 启动

需要 Node.js 24.14 或更新的 24.x、pnpm 11。

```powershell
pnpm install --frozen-lockfile
pnpm assets:restore
pnpm assets:check
pnpm music:import
pnpm music:check
pnpm build
pnpm start
```

打开 <http://localhost:3000>。房主输入昵称并创建房间，朋友通过同一地址或六位房间码加入。全部玩家准备后，房主开始拓荒。企业配置在建房时选择。

公开仓库包含源码、规则数据和素材来源清单。运行图像与操作音效由 `assets:restore` 按 SHA-256 获取到本地，背景音乐由 `music:import` 从开发者本地 `music/` 导入；原始研究扫描及历史截图保存在开发者本地。未持有音乐原件时可跳过两项 `music:*` 命令，在声音设置关闭背景音乐。可设置 `ASSET_BASE_URL` 使用自己维护的素材源；素材权利见 [第三方说明](THIRD_PARTY_NOTICES.md)。

开发版新增素材可直接从原始公开来源重建：先安装 `tools/requirements.txt` 并运行 `python tools/prepare-table-experience.py`，再使用 `pnpm voices:acquire` 获取中日语音，最后执行 `assets:restore` 校验其余已发布素材。这条路径可在本轮云端验收前使用。语音采集需要 Playwright Chromium 与 FFmpeg，音乐封面提取也使用 FFmpeg；可通过 `FFMPEG_PATH` 指定程序路径。测量参数和出处见 [本轮素材记录](assets/table-experience-art.md)。

另一台 Windows 电脑可使用预编译运行包：在开发电脑运行 `pnpm package:windows`，将生成的 `.data/releases/nomad-city-windows.zip` 复制过去完整解压。目标电脑安装 Node.js 24 后，双击 `start-game.cmd` 启动；运行素材和服务端依赖已随包提供。局域网、隧道、配置检测及备份操作见 [Windows 运行说明](deploy/windows/START-HERE.txt)。

局域网朋友访问 `http://房主电脑的局域网IP:3000`。服务默认监听 `0.0.0.0`。Windows 可使用 `ipconfig` 查看局域网 IPv4 地址；如系统防火墙询问，允许该服务在私人网络上连接。所有人应使用固定的同一个主机地址，浏览器的席位凭证按站点保存在本地。

开发使用单一命令 `pnpm dev`，打开 <http://localhost:5173>。该命令同时运行规则服务及 Vite。生产启动只需要 3000 端口。

## 对局与恢复

- 首页以纸质拓荒许可、四张原版企业家卡牌和暖褐荒野组成；可直接建房、填写房间码后回车加入，邀请链接会显示对应拓荒区。背景缓慢漂移，卡牌依次入场，系统减少动态效果设置会停用装饰动画。
- 房间大厅以四张企业家席位板展示立绘、城市棋子、本人／房主、在线与准备状态。点击空席或档案中的邀请按钮可分享房间；全员准备后由房主确认开始，离线玩家保留席位。页面显示准备进度、本局配置及棋盘缩略图。设计与素材复用见 [入口与集结桌](assets/entry-lobby-art.md)。
- 房主可在“邀请朋友 → 人机同行”添加或移除人机席位；点击大厅空席也打开同一凭证。支持一位真人加 1–3 位人机，或朋友与人机混合组成 2–4 人对局。人机自动准备、选牌、行动和采集，各自计分，开局后锁定席位。策略使用正常玩家视图比较资源收益、建设和区域控制；人机不会读取其他玩家秘密手牌或牌库顺序。所有真人离线时暂停自动行动，恢复连接后继续已保存的待选步骤。
- 角色手牌在底部扇形展开，包含罗德岛招募的角色；悬停单张牌会抬起放大，鼠标离开扇面后自动收回，已选牌保留。移向确认区时扇面保持展开。所有玩家同时点选、预览和秘密盖放，最后一位确认后开始行动；左右方向键切换卡牌，回车选中，Escape 收起并取消本地预览。行动和事件从地图旁打开窗口。
- 顶部常驻“新手教程”和“功能查询”。六节教程提供选牌盖放、城市移动和采集路线的独立演示；查询可按关键词和类别检索操作、角色、设施与企业，牌文直接取自规则数据。教程练习与查看资料均不提交对局指令。
- “实操练习”与教程中的“进入实操教程”打开正式棋桌的独立练习场景，共七课：秘密盖放、影响力部署、城市移动、探索事件、设施建设、角色策略和并行采集。操作使用正式规则裁定，人机教练安排自己的选择；每课准备相应资源和地图场景，完成后亲自进入下一课。支持重练、退出及刷新后继续，进度仅保存在本机，不修改原联机房间。
- 房间码输入区与分享窗口采用通行凭证样式。加入房间、开始游戏时显示短过场，可按 Escape 或“跳过动画”结束；刷新与重连不重播。准备、加入、确认等按钮提供按下回弹反馈，网络等待期间阻止重复操作；系统减少动态效果设置会关闭按钮动画并缩短过场。
- 侧边资源盘与地图资源标记使用官方图标，数值增减带翻动提示。原版企业家立绘位于地图左侧，当前操作提示在立绘上方；大总统使用带底座、厚度与转动效果的立体立牌，跟随起始玩家。
- 回合末所有玩家同时规划采集，在地图逐点勾选、撤回并核对共用航道路费，选择收款方后锁定自己的方案。全员确认后才统一支付与领取资源；即使本次不采集，也需确认。探索和路费收款选择也在地图旁完成。
- 并行采集以进入该阶段时的金券为路费预算，本阶段收到的路费在全员确认后的结算中到账。这样每人的可选路线不受其他人确认先后的影响；结算日志按大总统起始顺序记录。这是本项目的联机流程约定，行动中角色能力触发的单人采集仍按能力顺序处理。
- 侧边显示每人的完成状态和全员确认进度；别人提交时保留自己的抬牌、路线与收款人预览。已确认玩家等待剩余席位，待选玩家断线时继续等待，重新进入原房间即可接续。
- 拖起自己的城市会显示可达位置，松手预览目的地与费用，确认后移动；键盘和点选入口同时保留。分数标记沿地图边缘更新，每位玩家的回合有中央动画提示。
- 主要行动阶段可直接点击地图高亮位置或空格上的“＋”放置影响力。企业家立绘上方显示落点、空位和标记储备变化，点击“确认放置”后执行部署；改选、取消或 Escape 撤回均不消耗主要行动。待放置步骤刷新后也能从地图继续，原行动窗口入口同时保留。
- 可移动的影响力也可直接拖起，虚线圈标出全部合法空位，松手预览、确认落子；连续调度和中途刷新均能接续。无效落点或取消不提交指令。影响力使用带金属底沿与席位符号的立体棋子，实际转移时播放落位动画。
- 设施供应区可查看牌面并进入建设，依次选择城市格与付款方式。宣告时展示样式牌及实际使用的设施组合；建设、补牌和宣告结果停留到点击“继续拓荒”。
- 城市、设施与企业使用侧边缩略图打开，日志位于地图旁。原图上的回合和终局说明移到地图边缘，悬停展开、点击固定。棋盘支持全屏、100%–300% 缩放和空白处拖动，牌面详情支持继续放大。
- 城市详情以 3 列 × 4 行缩略盘展示实际格位；悬停建筑或用方向键移动焦点，旁边显示原牌面、效果与样式使用状态，点击可继续放大。窗口顶部可直接切换玩家，资源盘同步显示对应玩家的持有数量。
- 每位企业家下方常驻显示五种资源的官方图标和数量，分数单列；点击玩家打开其城市与资源。资源变化实时翻数，切换查看对象只切换余额。
- 合作企业窗口采用八家原版企业板与品牌配色，支持高清放大。0–5 级轨道显示全体玩家棋子，并区分企业特效、升级奖励和当前／下一等级；可切换玩家查看进度，展开全体等级对照。莱茵生命三个科室支持独立预览，当前激活科室始终单独标明。素材说明见 [合作企业板](assets/enterprise-boards.md)。
- 行动、建设和结算窗口采用纸面与黄铜框，确认区固定在底部。选择合作企业时以官方品牌抬头组成并列档案卡，选中展开各级能力；升级及同企业的不同特效明确显示目标等级，完整原板可单独查看。
- 探索事件直接翻开原版事件卡，结果按钮并列放在卡面下方，使用官方资源图标。点击高亮选择，可取消或改选，确认后才结算；绿色、黄色与红色事件沿用牌面强调色，企业扩展自动展示对应替换卡。查看详情、关闭和刷新均不代选结果。
- 棋盘使用 5000×5000 原扫描，基础角色详情使用 1200×1700 原扫描，牌面按完整比例展示。
- 顶部合并为单行；棋盘去除原印刷边框与说明纸片，以 AI 地形补绘填充边角，原道路和交互坐标独立保留。桌面背景使用《铸基者》官网宣传图并轻微漂移，系统减少动态效果设置会关闭装饰动画。来源和生成提示见 [扇形棋桌素材记录](assets/fan-table-art.md)。

- 每位玩家使用自己的浏览器或独立浏览器配置入座。无痕窗口可用于临时测试。
- 同一席位只保留一个活动标签页；在另一页打开该席位时，原页提示席位已转移。
- 开局后锁定席位。断线保留席位，等待其行动或选择，恢复连接后继续。
- 每条有效指令在 SQLite 事务中保存，再广播；重复编号返回已保存回执。普通行动校验房间版本，并行阶段另校验每人独立的选择版本：朋友提交不使自己的方案过期，本人改选或阶段结束后旧选择失效。
- 手牌、秘密盖放角色、秘密选择和私人日志按玩家投影，牌库顺序及随机状态留在服务端。
- 服务重启后使用原浏览器和原房间地址恢复。浏览器清除站点数据会清除该浏览器的席位凭证。
- 存档记录规则版本；升级服务时保留旧版本的代码或容器，以便继续既有对局。

默认数据库为 `.data/state/nomad-city.sqlite`，默认备份目录为 `backups/`。

## 验证

```powershell
pnpm check
pnpm test
pnpm assets:check
pnpm build
pnpm exec playwright install chromium firefox
pnpm browsers:prepare
pnpm test:e2e
```

浏览器项目覆盖 Chromium、系统 Microsoft Edge 和 Firefox，分辨率为 1920×1080 与 1366×768。整局测试同时验证服务端状态重放和实际浏览器 WebSocket 同步，自动对局属于回归验收，朋友试玩按 [验收记录](docs/acceptance.md) 执行。

安装 Playwright 浏览器需要网络；Edge 项目需要本机安装 Microsoft Edge。测试使用独立临时数据库和 3011 端口，不修改试玩数据库。

## 备份与恢复

已部署的云端入口：[http://106.52.74.24](http://106.52.74.24)，管理与备份步骤见 [云端运行](docs/cloud-server.md)。本地房间与云端房间分别保存。

公网开服的选购、上传、安装、HTTPS、备份和停服步骤见 [公网部署说明](docs/deployment.md)。本地运行 `pnpm package:deploy` 生成可上传的部署包和 SHA-256 校验文件。

运行服务每 24 小时创建 SQLite 在线备份，默认保留最近 7 份自动备份，手动备份单独保留。公网防护、连接限制与运维边界见 [安全说明](SECURITY.md)。也可手动执行：

```powershell
pnpm backup
```

备份包含房间、完整对局状态、等待选择、随机状态、操作日志及指令回执。客户端的席位凭证仍由各玩家原浏览器保管。

恢复时先在服务终端按 `Ctrl+C` 停止服务，将 `nomad-city.sqlite`、同名 `-wal`、`-shm` 文件一起移入单独的留存目录，再将选定的备份复制为 `.data/state/nomad-city.sqlite`。启动 `pnpm start`，通过健康检查和原房间核对版本、阶段与日志。保留恢复前数据库及备份，避免覆盖唯一存档。容器恢复步骤见 [部署说明](docs/deployment.md)。

## 结构

| 目录                  | 内容                                                                     |
| --------------------- | ------------------------------------------------------------------------ |
| `packages/rules/src/` | 独立、可序列化的规则状态机；配件数据、合法行动、指令执行、玩家投影和计分 |
| `apps/server/src/`    | HTTP、WebSocket、席位验证、房间串行执行、SQLite 与备份                   |
| `apps/web/src/`       | React 界面、原图背景与 SVG 交互层、卡牌、城市和日志                      |
| `assets/`             | 配件目录与素材来源、处理参数、SHA-256 清单                               |
| `tests/`              | 规则、卡牌、服务恢复及浏览器验收                                         |
| `tools/`              | 开发启动、备份、公开资料读取、素材归一化及校验                           |
| `deploy/`             | Caddy 配置；根目录另有 Dockerfile 与 Compose                             |

已归一化素材随项目运行目录提供，启动游戏不需要重新下载。重建素材使用 `python -m pip install -r tools/requirements.txt`，依次运行 `tools/research.py`、`tools/extract-tabletop.py`、`tools/import-assets.py`、`tools/prepare-hd-assets.py`、`tools/prepare-table-motion-assets.py`、`tools/prepare-fan-assets.py`，再运行 `pnpm assets:catalog` 和 `pnpm assets:check`。资料脚本只读取公开内容，不执行模组里的 Lua 脚本。

项目用于朋友私人试玩。原画及桌游素材权利归原作者；公开下载地址本身不构成素材再分发授权。出处及处理记录保存在 `assets/manifest.json`。
