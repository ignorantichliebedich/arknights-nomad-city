# 版本与发布

应用版本使用 `package.json` 的 `major.minor.patch`，从本轮 v0.2.0 起每轮交付递增。界面、音乐和网络调整改变应用版本；规则版本 `founders-2023.1` 只有规则或存档兼容性变更时单独处理。

感染者房间使用 `oripathy-2024.1111`；基础版及原企业扩展存档继续使用 `founders-2023.1`。部署包须同时包含两个规则包及感染者运行素材，不修改已有房间的规则标识。

## 自动整理版本

```powershell
pnpm release:prepare --type minor --note '接入背景音乐与播放控制'
pnpm release:check --base origin/main
pnpm build
```

默认不指定 `--type` 时递增 patch；新增功能使用 minor。脚本同时更新版本和更新记录，顶部及声音设置显示构建版本。整理版本后有本轮修正时先完成验证，推送前检查清单一致；新的交付轮次再递增。

GitHub 检查对比本次推送前或 PR 基线版本，要求版本递增，且更新记录最新条目匹配。CI 保留完整 Git 历史供比较，只有检查任务，不含发布密钥或部署步骤。

## 本地验收后上线

1. 本地完成相关测试、构建和公开文件审计，提交并推送 GitHub，检查 CI。
2. 用户在本机试玩对应版本，核对音乐、操作、房间恢复和本次变化。
3. 用户明确确认该版本上线后，才准备服务器上传与部署。此前保持云端原版本运行。
4. 记录待部署版本与 Git 提交，制作部署包并校验摘要；音乐等运行素材由本机随包携带，不提交公开仓库。
5. 在服务器备份数据库，保留原镜像和配置，停服窗口内核对房间正文摘要、版本及回执，再更新到已验收版本。
6. 健康检查和公网浏览器流程通过后，下载备份，核对存档和已上线版本，记录结果；失败恢复旧镜像与配置。

每轮交付明确给出“待本地验收”状态；源码推送和云端上线分别记录。最近一次已确认云端发布为 v0.7.1（提交 `7b26e18`），[上线记录](releases/v0.7.1.md)列出存档核对、服务器备份及公网验收。本次仅发布已验收版本，应用与规则版本沿用该提交。后续版本先供本地验收，变更与检查记录见 `CHANGELOG.md` 和 [试玩与验收记录](acceptance.md)。联机性能测量与慢操作定位见 [四人联机延迟排查](network-performance.md)。
